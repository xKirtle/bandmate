# The Timeline plays decoded audio buffers on one Web Audio clock

Timeline playback fetches every Clip's audio, decodes it into memory and schedules it on a single `AudioContext`, rather than streaming each Clip through its own `<audio>` element. Tracks have to stay sample-accurate with each other, and Record (recording Takes over the Timeline, Latency Offset compensation) relies on one reliable clock. Separate `<audio>` elements drift against each other by tens of milliseconds and can't be scheduled precisely. The cost is memory: a 4-minute stereo Beat decodes to roughly 90 MB, which is why the Timeline is edited on desktop and only played back on phone. Masters and Beat previews aren't part of the Timeline and play through plain `<audio>` elements, streamed with HTTP Range requests.
