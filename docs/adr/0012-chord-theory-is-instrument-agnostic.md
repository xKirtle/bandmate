# Chord theory knows no Instrument; each Instrument brings its own Voicings, drawing and input

The Chord Finder's three jobs share one core that knows nothing about any Instrument: a Chord name gives its notes, a set of notes gives the Chord names that fit it, and a Key gives the Chords that go with it. Each Instrument brings the rest: how it voices a Chord, how it draws a Voicing, and how the user places notes on it to name a Chord. The guitar is the only Instrument at first. Its Voicings are generated by searching the fretboard of the tuning in use for playable shapes and ranking them, not read from a table of hand-picked shapes. A piano would be a new Instrument with its own Voicings (inversions within a hand's span), a keyboard drawing and key input, and would change neither the core nor Suggest.

The alternative was to model only fretted Instruments (strings, tuning, frets), which is all the guitar needs. But a piano doesn't fit that model, and keying theory to strings would mean reworking Name it and Suggest to add one. Generating guitar Voicings, instead of keeping a hand-picked table, is what lets Voicings follow any tuning a Song uses (Drop D, DADGAD, half-step down) without a table for each. The cost is ranking: generated Voicings take tuning to look like the ones a player would choose. The user's preferred Voicings, kept on each device, refer to generated shapes, so switching to a table later would shift what they point at.
