# A Backup is a small Bandmate database, brought up to date by the migrations on Restore

A Backup is one file holding a database with only the chosen Songs and Beats, at the schema of the Bandmate that made it, plus the audio and Covers those rows use. A Restore copies that database aside, runs the existing migrations on it to bring it up to the current schema, then copies the chosen rows into the live database with fresh local ids, matching Songs and Beats by an identity that survives moving installs rather than by those ids. The Backup file itself is never changed. So a Backup from an older Bandmate restores through migrations already written and tested, and one recording a migration this Bandmate doesn't know came from a newer one, and is refused.

The alternative was a versioned document (JSON plus the files) that's readable on its own. It would need a hand-written upgrade step for every schema change, kept forever and tested against every old version, duplicating what the migrations already do. The cost of this choice is that a Backup can only be read by Bandmate, and that every migration must keep working on a database holding only some Songs and Beats, not just on a whole install.
