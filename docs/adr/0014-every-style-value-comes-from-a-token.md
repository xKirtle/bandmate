# Every style value comes from a token, and content and tools speak differently

Every colour, font size, space, radius, shadow and duration in the web app comes from a token defined once in the global stylesheet, and Stylelint fails CI on a literal value anywhere else. The look had grown screen by screen into about 15 font sizes, 8 radii and 77 distinct gaps and paddings, and the UI written by agents had nothing to hold it to. Tokens are also what make Palettes possible: a Palette swaps the colour tokens' values, and only a component that uses them follows it. A value the scale lacks becomes a new token, not a one-off, which costs a little friction on every new screen. That friction is the point.

Within those tokens, content and tools are treated differently. Content, what the user wrote (Lines, Chords, Labels, a Song's title and notes, the Scrapbook), gets room and Read mode's larger lyric sizes. Tools, such as the Timeline, transport, toolbars and dialogs, are denser and quieter, with tabular digits. A single, uniform voice was the alternative. A notebook typeface for content was prototyped too, and dropped: the system font stays everywhere, and the difference is carried by size and spacing alone. See [the design doc](../design.md).
