# Snapshots thin by the day where they were taken

Snapshots are thinned to the newest of each day, then of each week (#995). That day used to be a UTC day, which splits a user's evening across two days when they're far from UTC: in New Zealand a UTC day runs from noon to noon, so Monday night's last Snapshot is thinned away in favour of Tuesday morning's. Now the browser sends its time zone with every request, and each Snapshot is stamped with its local date as it's taken: the date on the Device whose change took it. Thinning keeps the newest of each such date, and of each date's ISO week. The stamp never changes, so which Snapshot is the newest of its day still never changes as they age. Snapshots taken before the stamp existed, and those in older Backups, keep their UTC date.

One time zone for the whole install, stored on the server and set in Settings, was the alternative. Bandmate can be opened from more than one Device, though, and a user who travels would have to remember to change it, or every day after would be split wrongly. The server's `TZ` was rejected because it's UTC in Docker unless the admin sets it, and the admin isn't always the one writing. Worked out from a stored zone name each time, the day could be read differently once the zone database changes, so only the date is kept.
