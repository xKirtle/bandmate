# Timeline placement rules are checked once, on what a change leaves

The Timeline's placement rules are checked once, on the Timeline a change leaves, never a Clip at a time partway through the change. The rules are: a Clip starts on the Timeline; no two Clips on a Track overlap; a Clip stays within its source; and its Fades fit it. Operations write their Clips without checking where they land. Every change runs through one path, which reads the Timeline before and after and hands both to one pure check, `checkLayout`. The check looks only at the Clips the change made or altered, so a Song whose stored layout is already slightly off never refuses the edit that would fix it. It returns which rule broke on which Clip, not a message, so an operation can put a refusal in its own words, as nudging a Take does with "trim it first".

Checking each Clip as it was written made the order of writing matter. Moving several Clips had to store them all before checking any. Setting several Tempos had to go latest-first and pass along the Clips leaving. Getting that order wrong caused bugs, and the rules could only be tested by driving the whole HTTP server. Checking the result instead makes order irrelevant, and the rules are table-tested on plain Timeline values. The cost is reading the Timeline once more per change. The write is since ordered once too, by ADR 0025: every change writes the whole Timeline through one writer, so write order is nothing an operation decides any more, and this paragraph's hazards are history. The database still refuses a Clip that starts before 0:00 or before its source, or that plays for no time, and those three were refused a Clip at a time as it was written, in the rule's own words; they are part of the one check now, which refuses them in the same words before anything is written. No operation should add per-Clip placement checks back. The searches for where a Clip fits (adding a Beat or a Sound, a Duplicate, a slowed Clip's new Track) find a place rather than refuse one. They search the Timeline the change starts from, testing for overlaps as the check does, never the database.
