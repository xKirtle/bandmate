# Every Lyric Sheet edit is a pure change to the whole sheet

Every change to a Song's Lyric Sheet and Scrapbook runs through one path: load the whole sheet, make the change to it as a pure function of the sheet, check the sheet it leaves with one check, `checkChange`, and write that through one writer, `writeSheet`. It extends ADR 0019, where Undo puts a whole copy of the sheet back, from Undo to every edit.

The writer compares the sheet it's given with the rows stored, and inserts, updates and deletes only those that differ: Sections (Label and place in the Arrangement or the Scrapbook), Alternates (name, whether active, and Section) and Lines (text, place and Cue). It writes exactly the sheet it's given, Cues included, so keeping a Line's current Cue, as Undo and a Snapshot restore do, is a step of their own before it. A pure edit that adds rows takes their ids from an id source it's handed, which counts up from each table's last-used id, and the writer inserts them as they are, as a restore does when it brings rows back. The sheet's tables are AUTOINCREMENT, so an id is never used twice, deleted or not.

The check covers each Section in exactly one of the Arrangement and the Scrapbook, once; no id held twice; exactly one active Alternate in each Section; no line break in a Line; and valid Cues. The database itself holds the first two for any stored sheet, so they're checked on the whole sheet. It doesn't hold the rest, so, as with the Timeline's placement rules (ADR 0023), they're checked only on what the change made or altered: a stored sheet that already breaks one never refuses an edit. Undo, the one path that takes ids from outside, also checks they're this Song's.

About 15 edits kept each Section's place in the Arrangement and the Scrapbook right by hand with SQL, while the check and a whole-sheet writer were used only by Undo and Snapshot restore, so the same rules were enforced twice, and Undo could drift from the edits it reverses. Undo and Snapshot restore moved onto the path first; the other edits follow, and no new edit should write the sheet's rows itself. The cost is loading the whole sheet on every edit, which is a few KB, and comparing it with what's stored.
