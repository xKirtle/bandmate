# A refused save shows in one toast stack

Every save the Song page is refused shows the same way: a toast in one stack at the corner of the window, labelled with the surface the edit came from. The Song page has four surfaces that can refuse a save, and `Saves` already tells them apart by the method the edit arrives through — `submit`, `typing` and `report` are the Details, `edit` and `make` are the Timeline, `cue` is the Cues, `changeLyricSheet` is the Lyric Sheet. An undo or a redo takes its surface from the kind of the `HistoryEdit` it replays. Nothing passes a surface along as a tag, because nothing has to: the method the caller already chose says which surface it is, and a tag could drift out of step with it.

Before this there was one `saveError` string for the whole page, drawn as a line after the Details. A Timeline edit refused in the dock at the bottom of the window reported itself under Tags, half a page up, reading as though the Tags field were the thing that failed. The line sits after the fields rather than before them on purpose: moving it above them reflows them, and an open Combobox's option list reflows with them, which is what reverted the first attempt at this — an end-to-end test clicked where "Drop D" used to be. The placement was never the mistake. The mistake was one error for four surfaces.

The Timeline made that plain: it already had a floating bar of its own, above the docked panel, carrying the refusals it works out for itself — an import that doesn't fit, a merge that can't be made. So a Timeline problem landed in one of two places depending on whether the client refused it or the server did. That bar is now gone and its messages join the stack, because a surface with two mouths is the same defect in smaller print.

Three shapes were built on the real Song page and compared side by side, on a wide window and at phone width, with a refusal fired from all four surfaces at once.

**A line anchored in each surface** keeps every message beside the thing it is about, and needs no new pattern — the Timeline keeps its bar, the others get a line. It was rejected on what it does to the page. Each line is in the flow, so each one reflows what is under it: the exact failure that reverted the first attempt, now in four places instead of one. At phone width four refusals pushed the first lyric off the screen entirely.

**A toast anchored over the surface that raised it** was the most promising on paper: immediate like a toast, local like a line, and floating, so it reflows nothing. In practice it covers what it is about. The Details toast sat squarely over Key, BPM and Capo — an error telling you a Capo value is wrong, hiding the Capo field. Anchoring could be nudged case by case, but a rule that needs an exception per surface is four placements wearing one name.

**One stack** gives up locality and buys it back with a label. It is the only one of the three that is immediate, never reflows, and never covers the field in question. The cost is real and accepted: an error is no longer beside its cause, so `Timeline` or `Lyric Sheet` on the toast is doing work that proximity used to do. That is why the label is not optional, and why it names the surface rather than the Clip — an edit can span several Clips, so a Clip name is a guess, while the surface is always the thing you would look at.

A toast **stays until it is answered**, never on a timer. The app's one comparable thing, the Lyric Sheet's notice, clears itself after five seconds, which suits what it says: a Section was moved, and the result is on the screen in front of you. A refused save is the opposite. "Couldn't save the Cue of Line 1, so it was taken back" is the only record that the edit is gone, and a message that removes itself while you are looking somewhere else loses work quietly. It clears when that surface's own next save lands, or when it is dismissed — that surface's own, because a Details save landing says nothing about whether a Timeline edit stuck, and clearing on any save at all would swallow a real failure the moment you tabbed out of a field.

One error per surface, so four at most, which the stack's bounded height holds. Nothing collapses them behind a count: four at once needs four independent failures, and a mechanism built for that would never be seen.

The "changed elsewhere" banner stays where it is, a block on the page rather than a toast. It is not a refusal that has passed; it is a standing state, with a paragraph to read and a Reload to press, and it should hold the page rather than queue behind a mistyped BPM.

This covers the Song page's refused saves and nothing else. The app has around twenty other error lines, in dialogs, cards and fields, and almost all of them already sit against the thing that failed — a Latency Offset typed wrong says so under the field, and moving that into a corner of the window would be this decision applied where its reasoning doesn't hold.

ADR 0030 extends the stack to one more toast with nowhere beside its cause to live: a Chord that couldn't be heard, its Instrument's samples not loading, on the Song page and the Chord Finder's page.
